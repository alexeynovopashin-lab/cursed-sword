# Команда чатов «Проклятого меча» — роли и регламент (черновик, 30.09.2026)

Заменяет прежние чаты итераций (героев, схем, исполнитель шага, диалоги,
плейтест). Все прежние чаты, кроме оркестратора, Алексей архивирует; работа
начинается заново с состояния `docs/NEXT_SESSION.md`. Чаты друг друга не видят:
всё, что нужно знать, лежит в файлах репозитория. Чаты не получают память
проекта — только файлы.

## Роли

| Чат | Делает | Главный результат | Модель (рекомендация) |
|---|---|---|---|
| **Оркестратор** | режет работу на шаги, принимает отчёты, ведёт состояние, единственный пушит | `NEXT_SESSION.md`, `ITERATIONS.md`, порядок чатов | Opus |
| **Сценарий** | сюжет: серии, акты, библия, сверка сезона со скелетом | `docs/story/season1.md`, `bible.md` | Opus |
| **Диалоги** | голоса героев, реплики, рассказчик, читаемость вслух | `docs/story/dialogue_*.md`, `docs/story/dialogues/` | Opus |
| **Механики** | правила игры: упрощённая D&D, статы, состояния, броски, бой | `docs/mechanics/` | Sonnet |
| **Геймплей** | как игрок играет: действия, ход, фразы, отказы, отряд 1–4 | `docs/gameplay/` | Sonnet |
| **Локации и звук** | места, схемы, бестиарий; фон, интершум, музыка по локациям | `docs/world/`, страницы доски про места | Sonnet |
| **Бета игры** | единственный, кто пишет код беты: разбор фраз, движок, интерфейс | `docs/visual/beta/` | Sonnet |
| **Тест игры** | только играет и проверяет, ничего не чинит | `docs/tests/` | Sonnet |
| **Литератор** | вычитывает тексты на слух до Алексея: согласование, «ты/вы», точка зрения, повторы, погружение; ведёт проверку текста (скрипт); выводит правила из правок Алексея | `docs/story/literary/` | Opus |

В запасе (открывает оркестратор, когда Алексей скажет): **Техника** —
облако, функция, навык, модели разбора (фаза 3, по слову Алексея);
**Озвучка** — тест колонки и звуки, когда придёт время записи.

`SESSIONS_CHAT.md`.

## Порядок работы чата (каждый шаг)

1. `git log --oneline -10`, затем `docs/NEXT_SESSION.md`, затем свой промпт
   (`docs/team/prompts/<роль>.md`) и свою задачу в `ITERATIONS.md`. Из
   `SESSIONS_CHAT.md` — `grep -n` по своей роли и «всем», плюс `tail -80`.
2. Перед правкой на ход больше одного файла дай в чате план в 10–15 строк и
   жди слова Алексея или оркестратора. Мелкие обратимые правки внутри своих
   файлов — сразу, скажи что сделал.
3. Проза — Алексея: всё, что написал агент, помечено «черновик». Канон не
   менять; в `DECISIONS.md` чаты не пишут.
4. Шаг меньше ~300 тыс. токенов. Контекст у ~250 тыс. или шаг сделан — итог,
   запись, коммит, отчёт, стоп. Замечания Алексея после проверки идут в
   **отдельный** шаг новым чатом, не в чат, который это делал.
5. Числа до выводов; то, чего не проверил, — в «не проверено», а не молча.

## Запись в диалог проекта

Только в конец `SESSIONS_CHAT.md`, одной командой:

```
cat >> /Users/alexey/Documents/workspace/10_projects/cursed_sword/SESSIONS_CHAT.md <<'EOF'
### 2026-09-30 15:21 · <роль> → <оркестратору | роли | всем>
**Тема:** одна строка
Что сделано, где лежит (коммит), что открыто.
**Жду:** от кого и что — или «ничего, для сведения»
EOF
```

Подпись — роль и задача своими словами. Старые записи не править.
«Правлю файл X, не трогайте» — запись перед началом. Без токенов и паролей.

## Отчёт оркестратору (в чат и записью)

```
ОТЧЁТ: <роль>, шаг K из M
  коммит: <sha>; в GitHub: нет (пушит оркестратор)
  сделано: 3–5 строк, по-русски, про игру, не про код
  «готово, когда»: да/нет — проверка из задания
  числа: что измерено (не впечатления)
  не проверено: …
  Алексею: развилки — 2–3 варианта, плюс и минус каждого, мой выбор и почему
  чужие файлы: что заметил несогласованного (не правил)
  контекст: ~N тыс. (оценка)
```

## Коммиты и пуш

- Чат коммитит **только свои файлы, по именам** (`git add <файл>`), без
  `add -A`, `add .`, `commit -a`, `--amend`. Чужие незакоммиченные правки —
  назвать, не трогать.
- Перед коммитом `git pull --ff-only`. Отказ может быть ложным (параллельные
  чаты): сверь `git reflog show main -5` и `git diff --stat HEAD`, прежде чем
  считать чужой работой.
- Заголовок коммита — что изменилось для человека («Габ говорит короче, шутка
  про сундук убрана»), не «правки». Тело — зачем и чего стоило.
- Без `checkout`, `switch`, `restore`, `stash`, `clean`, `rebase`, `reset`,
  force. Отказ хука — «сотрёт чужую работу», обходить нельзя.
- **Пушит только оркестратор и только по слову Алексея.** Перед пушем
  `git fetch`, `git pull --ff-only`, никогда force. После пуша страницы
  доски: `curl -so /dev/null -w "%{http_code}" <адрес>`.
- Бета на GitHub Pages публикуется только по слову Алексея; перед публикацией
  — отчёт теста игры без «ломает».
- Один тяжёлый чат за раз (код беты, тесты); остальные — лёгкие (документы,
  чтение).
- Новая инфраструктура (облако, навык, хранилище, ключи, платежи) — только по
  слову Алексея. Ключей и паролей в файлах нет.

## Как вопросы доходят до Алексея

Через оркестратора, по правилу 29 workspace: 1–3 фразы, зачем и в чём
развилка; 2–3 конкретных варианта «что произойдёт в игре», плюс и минус,
мой выбор. Чат не задаёт Алексею абстрактных вопросов напрямую; то, что нужно
решить, идёт в «Алексею» отчёта.

## Каналы между ролями (кому что передаёт)

- Сценарий → Диалоги: принятые серии. Диалоги → Бета: принятые реплики.
- Механики → Бета: правила и числа; Бета → Механики: что не вышло или не
  считается.
- Геймплей → Бета: словарь действий и отказы; Бета → Геймплей: список фраз,
  которые игра не разобрала.
- Локации и звук → Бета: описания, схемы, списки звуков. Звуки → Озвучка.
- Диалоги / Сценарий → Литератор: готовый текст до показа Алексею; Литератор → владелец: замечания списком «цитата → что не так → как поправить». Литератор текст не переписывает. Правки Алексея руками — главный источник правил: Литератор сравнивает его версию с черновиком и дополняет гид «правилами из правок».
- Тест → оркестратор → нужный владелец: ошибки по файлам-владельцам, не всем
  подряд.
