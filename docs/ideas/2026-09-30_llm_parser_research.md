# LLM как семантический разбор фразы игрока — исследование

**Черновик, 2026-09-30.** Идея: модель превращает свободную фразу («толкаю дверь, беру сундук и подпираю») в список действий, решает и рассказывает наш детерминированный движок. Пометки: «из источника» / «не удалось проверить» / «оценка агента». Ничего не мерено. Связанный файл: `2026-09-30_alice_skill_capabilities.md` (4,5 с, 1024 симв., state 1 КБ).

## 2. Влезает ли в 4,5 с

- Бюджет 4,5 с — на всё: соединение, обработка, ответ (capabilities.md п.7). В 2023 разработчик писал про «ровно 3 секунды» (https://habr.com/ru/articles/725704/) — сейчас документация говорит 4,5; расхождение, брать меньшее как запас (оценка агента).
- Опыт с ChatGPT в навыке (Habr 725704, из источника): ответ ChatGPT не укладывался; обход — «Не успел получить ответ. Спросите позже» и повторный запрос; собственных замеров задержки автор не привёл.
- Холодный старт Yandex Cloud Functions: для .NET Hello World — 216,6 мс (JIT), Native AOT — 28,8 мс, тёплый — 1,2 мс (https://habr.com/ru/articles/819213/); в документации для «Hello world» ~150 мс vs ~1 мс (пересказ поиска). Это старт пустой функции, не с большим зависимостями; наш реальный старт — измерить.
- **Provisioned instances** в Cloud Functions: «экземпляр без холодного старта», интерпретатор и код инициализированы заранее; платятся отдельно простой и выполнение, ставки в пересказе не найдены (https://yandex.cloud/ru/docs/functions/concepts/function). Стоимость — не удалось проверить.
- Компоненты бюджета (оценка агента, не измерено): сеть Яндекс→функция ~десятки мс; холодный старт 0,15–0,3 с (пустая) — больше при загрузке модели/библиотек; вызов LLM — единицы секунд для нескольких десятков выходных токенов у модели неизвестной скорости. Для JSON с 3–6 короткими действиями (~40–80 токенов) при ~50–200 ток/с это 0,3–1,5 с + TTFT — **только оценка, замерить на Yandex Lite / Alice AI Flash / GigaChat Lite**.
- Приёмы: (1) короткий промпт + кэш префикса (кэшированные токены −75%, Yandex); (2) маленькая модель (Lite/Flash); (3) сначала правила, LLM только на неразобранное; (4) жёсткий таймаут запроса к LLM ~2,5–3 с, при превышении — откат на правила/переспрос «не понял, повтори проще» (оценка агента); (5) стриминг не помогает: навык отвечает целиком, но можно остановить чтение при полном JSON; (6) ответ-заглушка + «спросите позже» — плохо для игры.
- Постоянный сервер vs функция: сервер не имеет холодного старта, но платный 24/7 и без автомасштаба; функция бесплатна для навыков Алисы по пересказу поиска (не первичный источник; не удалось проверить). Оценка агента: для прототипа функция + provisioned instance или пингер, для серии — сравнить цены измерением.

## 3. Экономика (оценка агента; арифметика по ценам раздела 1)

Допущение: промпт 500 токенов входа (с кэшем префикса часть дешевле), выход 60 токенов.
- YandexGPT Lite: 500×0,2/1000 + 60×0,2/1000 = 0,10 + 0,012 = **~0,11 ₽/реплика**.
- Alice AI LLM Flash: 0,05 + 0,012 = **~0,06 ₽**.
- gpt-oss-20b: 0,05+0,006 = **~0,06 ₽**.
- Pro 5.1: 0,4+0,048 = **~0,45 ₽**. Alice AI LLM: 0,25+0,072 = **~0,32 ₽**.
- GigaChat Lite по пакету: ~0,065 ₽/1000 → (560 токенов) **~0,04 ₽**.
- Сессия 30–60 реплик: Lite 3,3–6,6 ₽; Flash 1,8–3,6 ₽; Pro 5.1 13,5–27 ₽. Если кэшировать префикс (−75% на кэшированной части), вход становится ~0,03–0,05 ₽ на Lite (зависит от доли префикса; не проверено, как считается кэш).
- Вывод для монетизации: при прежних допущениях затраты на разбор — единицы рублей на сессию; навык бесплатен для игрока (реклама в навыках запрещена, п.11 capabilities), платежи документацией неясны — значит платить придётся из своего кармана или через программу поощрения; масштаб: 1000 сессий/мес ≈ 2–7 тыс ₽ на Lite/Flash (оценка). Рассказ (генерация текста) LLM не предлагается — только разбор, поэтому длинных выходов нет.

## 4. Опыт разработчиков

Найдено мало; специализированных статей про D&D/квесты с LLM на Алисе **не нашёл** (поиск вернул общие материалы). Что есть:

- **kopakama/alice-smart-agent** — навык Алисы с LLM на Cloudflare Worker + KV (https://github.com/kopakama/alice-smart-agent; MIT). Архитектура: ждёт модель ~2,5 с; успела — отвечает сразу; нет — говорит «Секунду, думаю», результат кладёт в KV, отдаёт на следующей короткой реплике («ага»). Константы: `INLINE_WAIT_MS` ≤ ~2800 мс (автор считает лимит Алисы **~3 с**, не 4,5), `API_TIMEOUT_MS` ≤ ~28 с (лимит Cloudflare 30 с). Замеры автора на «сложном запросе», сентябрь 2026: deepseek-v4.1-flash ~2 с; gpt-6-luna 5–7 с; glm-5.3-flash 4–8 с; gpt-6-sol 20–35 с. Другой репозиторий (https://github.com/biglion62-art/alice-claudealice-yandex-skill) даёт те же числа, плюс, по пересказу поиска, aliceai-llm-latest ~1–1,5 с и claude-haiku-4-5 2–3 с (этой цифры на открытой странице не увидел — **не подтверждено**). Грабли автора: сообщение «думаю» слишком частое при медленной модели — надо менять модель; бесплатный Cloudflare KV — 1000 записей в сутки (~300–500 вопросов); прочее — лимит вопросов на пользователя (по умолчанию 100/сутки). Из источника, но это длинный ответ, а не короткий JSON — для разбора выход в разы короче, время, вероятно, ниже (оценка агента).
- **Расхождение по таймауту**: документация Диалогов — 4,5 с (capabilities.md); разработчики в статьях и репозиториях (Habr 2023 https://habr.com/ru/articles/725704/, infostart https://infostart.ru/1c/tools/1807166/, GitHub 2026) пишут «3 с» и держат внутренний лимит 2–2,8 с. Пока не измерено, считать рабочим бюджетом ~3 с, а не 4,5 (оценка агента; **проверить измерением на Станции и в консоли**).
- Habr 725704 (ChatGPT в Алисе, 2023): решения нет, только «не успел — спросите позже»; ограничения 1024 симв. и что навык не может сам начать разговор (из источника).
- infostart 1807166: приём `Promise.race()` — гонка запроса к API и таймера 2 с с ответом-заглушкой (из источника).
- Публичная страница требований: «навык проверяют целиком» (capabilities.md п.12); правил именно про генерируемый нейросетью текст в найденном **нет**; жалоб на отказы модерации по этой причине **не нашёл** (не удалось проверить; форум/чат разработчиков поиском не открывается).
- Наш случай отличается: LLM не пишет ответ игроку, а только разбирает фразу; текст рассказа детерминирован и его можно показать модерации заранее. Это снимает риск непредсказуемого текста в ответе (оценка агента), но не снимает `markup.dangerous_context`.
- Официальные примеры: https://github.com/yandex/alice-skills; список инструментов https://github.com/sameoldmadness/awesome-alice.

## 5. Локальные альтернативы без LLM

Цифры из поисковых пересказов, страницы целиком не читал; для нашей задачи (извлечение цепочки действий) прямых бенчмарков нет — **не удалось проверить**.

- **pymorphy2/3** (лемматизация): ~12 000 слов/с (по пересказу; https://habr.com/ru/articles/503420/ сравнивает лемматизаторы); форк mawo-pymorphy3 заявляет 10–20 тыс слов/с, старт 0,05–0,1 с, ~15–20 МБ (https://github.com/mawo-ru/mawo-pymorphy3 — заявление автора форка). Для фразы в 10–20 слов — порядка миллисекунд (оценка агента). Ограничение: платформа Алисы и так даёт `nlu.tokens` и грамматики с `%lemma`, то есть базовая нормализация бесплатно.
- **Natasha/Slovnet** (NER, морфология): 25 новостных статей/с на CPU, старт ~1 с, память ~205 МБ (пересказ, https://natasha.github.io/ner/). Для «игровых» сущностей (сундук, дверь) не нужна — их словарь мы знаем сами.
- **Rasa NLU**: в сравнении русскоязычных платформ (Ростелеком, https://habr.com/ru/companies/rostelecom/articles/695402/, пересказ) точность интентов 66% на большом наборе и 79% на малом, отклик ~11 мс. Тяжёлая зависимость; **не для функции с 4,5 с и малой памятью** (оценка агента). Цепочки действий («толкаю, беру, подпираю») Rasa разбирает плохо, это классификация одного интента + сущности.
- **Эмбеддинги** cointegrated/rubert-tiny2: CPU-задержка ~5,5 мс, вектор 312 (Hugging Face https://huggingface.co/cointegrated/rubert-tiny2; бенчмарк https://github.com/avidale/encodechka). Точность интентов 0,757 в найденном пересказе — датасет NLU-evaluation-data, вероятно не русский; переносить на наш словарь нельзя. Схема: сопоставить каждую подфразу с ближайшим известным действием из списка ~50–100 глаголов; нужен запуск модели (~30–120 МБ, оценка агента) — в Yandex Cloud Functions влезает не гарантированно; нужен сервер (не проверено).
- **Платформенные грамматики Алисы** (`nlu.intents`, `%lemma`): бесплатны, быстры, не расходуют наш бюджет времени; но интенты ограничены грамматиками, которые пишем вручную, и не понимают сложных цепочек; максимальный размер грамматики документацией не назван (capabilities.md п.2).
- **Правила + словарь глаголов** (наш код): токены → леммы (pymorphy или готовая таблица форм) → карта «глагол → действие», сущности из словаря сцены («сундук», «дверь»), разбиение на подфразы по «и», «,», «потом», «чтобы» (цель). Скорость — микросекунды; стоимость — ноль; точность на живой речи не измерена (оценка агента: разумно закрывает 70–90% типичных фраз в закрытой сцене — **это гипотеза, замерить на реальных репликах игроков**).
- Гибрид: правила → если не разобрано (остались значимые слова) → LLM с таймаутом → если не успел, переспросить.

## 6. Озвучка и экраны (дальняя цель)

**Свои звуки/записи актёров** (https://yandex.ru/dev/dialogs/alice/doc/ru/resource-sounds-upload, из источника, WebFetch-пересказ): MP3/WAV/OGG; ≤120 с на файл (длиннее обрезается); ≤5 МБ; 1 ГБ на навык (в сжатом OPUS); в `tts`: `<speaker audio='dialogs-upload/{skill-id}/{audio-id}.opus'>`. Теги звуков не входят в лимит tts 1024 (capabilities.md). Правил про авторские права и записанный голос страница не содержит; упоминает возможность загрузить голоса известных чтецов для новостных навыков. Что 1 ГБ значит: при ~5 МБ/файл — не меньше 200 файлов; в OPUS реальная длительность — оценка: сотни минут (битрейт не указан, **не проверено**). Полная запись серий актёрами упирается не в лимит, а в то, что реплика (движок) собирается из вариативных кусков: заранее записываются фиксированные фразы, а динамические (имена игроков, числа) озвучит синтез — стык голосов слышен (оценка агента).

**Голоса синтеза** (https://yandex.ru/dev/dialogs/alice/doc/ru/voices, из источника): 18 русских голосов; сторонний или свой голос в навыке **не разрешён** — только голоса платформы; менять голос внутри одного ответа документация не описывает (не удалось проверить). Не подражать Алисе.
- **Yandex SpeechKit Brand Voice** (клон голоса по записям актёра; https://aistudio.yandex.ru/docs/ru/speechkit/tts/brand-voice/): условия — согласие человека, чей голос записан; доступ к результату только заказчику; правила ограничивают сценарии применения (из поиска). Можно ли подключить такой голос в навык Диалогов как «голос навыка» — **не удалось проверить**; спросить поддержку.
- **ElevenLabs**: платные планы дают коммерческое использование (Starter $5/мес, 30 000 кредитов ≈ 30 мин TTS — обзорная статья, https://bigvu.tv/blog/elevenlabs-pricing-2026-plans-credits-commercial-rights-api-costs/); клонировать можно только голос, на который есть права/согласие (https://terms.law/ai-output-rights/elevenlabs/); ElevenLabs оставляет за собой вечную лицензию на обучение по загруженным голосам. Доступность и оплата из РФ — **не удалось проверить**. Схема: сгенерировать файлы вне навыка → загрузить как «свои звуки» (каждая фраза ≤120 с). Соответствие правилам навыка: документация Диалогов не запрещает и не разрешает предзаписанное аудио от синтеза, но модерация «оценивает содержание ответов» (capabilities.md п.12) — **уточнить у поддержки Диалогов до вложений** (оценка агента).
- Эффекты голоса не работают на голосе Алисы (capabilities.md) — значит, если нужен «голос меча», брать другой голос навыка или записанное аудио.

**Экраны** (из https://yandex.ru/dev/dialogs/alice/doc/ru/response и .../resource-upload, пересказ):
- Карточки: `BigImage`, `ItemsList` (1–5), `ImageGallery` (1–7). Кнопки: `title` до 64 симв., `url` до 1024 байт, `payload` до 4096 байт, `hide`.
- Картинки: PNG, JPEG, GIF, BMP, TIFF, WEBP; файл от 1 КБ до 1 МБ; квота 100 МБ на аккаунт; загрузка по HTTP API с OAuth (по URL или multipart), просмотр/удаление; при превышении — 429; в ответе — `image_id`. Соотношение сторон и рекомендованное разрешение в пересказе **не найдены**.
- Поддерживающие устройства и признак `meta.interfaces.screen` — см. capabilities.md п.5, п.13. Для безэкранных `text` обязателен.

**Рекомендация (оценка агента, не мерено):** C — гибрид. Сначала грамматики платформы + свои правила по леммам, LLM (Yandex Lite или Alice AI LLM Flash, JSON-схема) — только как запасной разбор с жёстким таймаутом ≤2,5 с; не успел — «Не расслышал, повтори проще» без потери хода (состояние не меняется). Причина: 4,5 с (а на практике ~3 с) включают холодный старт, а цена/риск LLM на КАЖДУЮ реплику не окупается, если правила берут большинство фраз. Рассказ и решения — движок, LLM их не пишет (согласуется с задачей).

**Что измерять самим:**
1. Реальный таймаут навыка (3 или 4,5 с): функция со `sleep` 3,2 / 4,0 / 4,6 с, по логам консоли и на Станции.
2. Холодный старт нашей функции (Python/Node, с нужными библиотеками) и p95; цена и эффект provisioned instances.
3. Задержка Yandex Lite, Alice AI LLM Flash, GigaChat Lite на промпте ~500 токенов и выходе 40–80 токенов JSON: p50/p95, 100 запросов, из функции Yandex Cloud (не с ноутбука); стабильность при 10 одновременных (квота).
4. Точность разбора на 100–200 реальных фраз (набрать у игроков): правила, LLM, гибрид; доля «не разобрано» правилами.
5. Стоимость на сессию: токены по факту (с кэшем префикса).
6. `markup.dangerous_context` на фразах вроде «бью гоблина мечом»; как модерация отнесётся к фэнтези-насилию; возрастной рейтинг.
7. Можно ли использовать SpeechKit Brand Voice как голос навыка и допустимо ли предзаписанное/синтезированное вне платформы аудио — вопрос в поддержку Диалогов.
8. Сколько минут озвучки реально вмещает 1 ГБ (загрузить пробный файл, посмотреть квоту).

**Что не удалось проверить:** задержки YandexGPT/Alice AI/GigaChat (нет опубликованных чисел), цена provisioned instances, доступность ElevenLabs из РФ, пределы квот Yandex сверх «10 одновременных», правила модерации для сгенерированного текста, требования к пропорциям картинок, опыт D&D-навыков (не найдены).
