# Возможности навыков Алисы — сводка из документации

**Черновик, 2026-09-30.** Источник: официальная документация https://yandex.ru/dev/dialogs/alice/doc/ru/ (страницы читались через WebFetch, который отдаёт пересказ, а не дословный текст — цифры стоит перепроверить на самой странице). Пометки: «из документации» / «не удалось проверить». Ничего не мерено на колонке.

Доступные разделы сейчас (оглавление документации): about, quickstart-about, guides-and-examples, surfaces, requirements, activation, procedure, prepare-steps, development, publish, request, response, skills-promotion-badge, skills-promotion-deeplink, rewards, earning, appmetrica, monitoring; отдельно session-persistence, speech-tuning. Заметка: оглавление не показало отдельных разделов про аудиоплеер, платежи, NLU-интенты, звуки и т.д. — возможно, они убраны из актуальной документации или лежат в других разделах (см. пункты).

## 1. Протокол webhook

- Обмен по HTTPS: платформа шлёт POST с JSON, навык отвечает JSON. Ссылка: .../ru/protocol (общая), .../ru/request, .../ru/response. Из документации.
- Запрос: блоки `meta`, `request`, `session`, `state`, `version` (1.0). `request.type`: `SimpleUtterance` (голос), `ButtonPressed`, `Show.Pull`. `session.new` — признак новой сессии. Из документации (.../ru/request).
- Ответ: обязательные `response` и `version`; необязательные `session_state`, `user_state_update`, `application_state`, `analytics`. `end_session` (boolean, обязательное) — завершить сессию. Из документации (.../ru/response).
- Лимиты: `text` до 1024 символов (может быть пустым, если есть `tts`); `tts` до 1024 символов (теги звуков не считаются). Из документации.
- Размер state: `session_state`, `user_state_update`, `application_state` — по 1 КБ JSON-объекта каждый. Из документации (.../ru/session-persistence). Совпадает с нашими замерами из `alice_soulledger` (ws:CLAUDE.md проекта).
- Таймаут ответа: в найденных страницах числа нет. Уточнено ниже: документация (.../ru/activation, .../ru/wait-response) называет **4,5 секунды**.
- Прочие поля запроса: `session.session_id` (до 64 симв.), `message_id` (счётчик), `skill_id`, `meta.locale`, `meta.timezone`, `meta.client_id` (до 1024, не рекомендуется), `meta.interfaces` (`screen`, `account_linking`, `audio_player`). Из документации.

## 2. NLU: интенты, сущности, токены, сырой текст

- Прочитанная страница .../ru/request в пересказе **не содержала** полей `nlu`, `markup`, `original_utterance`: — подробности найдены на других страницах, см. «Дополнения» ниже.

## 3. TTS-разметка

- Паузы: `sil <[мс]>`, например `sil <[1000]>` = 1 секунда; плюс автопауза 50–100 мс между знаком препинания и следующим словом. Из документации (.../ru/speech-tuning).
- Ударения: знак `+` перед ударной гласной (`остр+ота`). Из документации.
- Фонемы: `a aa b bb c ch d dd e ee f ff g gg h hh i ii j k kk l ll m mm n nn oo p pp r rr s sch schwa sh ss t tt u uu v vv y yy z zh zz pau`. Из документации.
- Звуки из библиотеки, свои звуки, эффекты голоса, смена голоса, шёпот: на странице speech-tuning в пересказе **не найдены** — не удалось проверить (см. дополнения ниже).

## Дополнения (найдено дальше; уточняют пункты 1–3)

- Таймаут ответа (п.1): страница activation говорит «превышение времени ответа — 4,5 секунды» → автоматический выход из навыка (.../ru/activation). Из документации. Также автовыход при некорректном формате ответа.
- Запуск: «запусти навык X», «запусти чат с X», «давай поиграем в X», «скажи/спроси у X <команда>»; текст после имени идёт в `request.command`. Выход: `end_session: true`; пользователь: «Алиса, вернись/хватит», «Стоп», «Закончить», «Выйти». Активно только одно приложение за раз. Из документации (.../ru/activation).
- NLU (п.2), из документации (.../ru/request-simpleutterance, .../ru/nlu): `request.command` — нормализованный текст (без пунктуации, нижний регистр); `original_utterance` — сырой текст, до 1024 символов (значение `ping` = проверочный запрос); `nlu.tokens` — массив слов; `nlu.entities` — типы `YANDEX.DATETIME`, `YANDEX.FIO`, `YANDEX.GEO`, `YANDEX.NUMBER` (в NLP-странице ещё `YANDEX.STRING`); `nlu.intents` — интенты из консоли; `markup.dangerous_context` (true при криминальном подтексте). Интенты: грамматики в консоли (`root`, `slots`, `filler`, операторы `[] ? * +`, директивы `%lemma %exact %negative %positive`); встроенные `YANDEX.CONFIRM/REJECT/HELP/REPEAT` (добавляются, если есть хотя бы один свой интент). Свои сущности — с `lemma: true`. Числовых лимитов на число интентов/размер грамматики в документации нет.
- TTS (п.3), из документации:
  - Звуки из библиотеки: `<speaker audio="alice-sounds-game-win-1.opus">`; 6 категорий (вещи, животные, игры, люди, музыка, природа); звуки с freesound.org, лицензия CC0 (.../ru/sounds). Теги звуков не входят в лимит `tts` 1024.
  - Свои звуки: MP3/WAV/OGG (конвертируются в OPUS), до 120 с (длиннее обрезается), до 5 МБ файл, 1 ГБ всего на навык (по сжатым), загрузка через консоль «Ресурсы → Звуки» или HTTP API; в `tts`: `<speaker audio='dialogs-upload/{skill_id}/{audio_id}.opus'>`; обработка асинхронная (.../ru/resource-sounds-upload). Битрейт/частота не указаны.
  - Эффекты голоса: `<speaker effect="имя">`, отмена `<speaker effect="-">`; behind_the_wall, hamster, megaphone, pitch_down, psychodelic, pulse, train_announce; **работают для всех голосов, кроме Алисы** (.../ru/speech-effects).
  - Голоса навыка: выбор одного голоса в консоли; русские: Филипп, Джейн, Омаж, Ермил, Захар, Мади, Даша, Юлия, Лера, Марина, Александр, Кирилл, Антон, Маша, Жанар, Сауле, Юлдуз, Замира (список из страницы, точность не перепроверена) (.../ru/voices). Смена голоса внутри одного ответа и шёпот на этой странице **не упомянуты** — не удалось проверить (ещё см. ниже).
- Связка аккаунтов (п.6): проверка `meta.interfaces.account_linking`; директива `start_account_linking` (в ответе без `response`); токен в `Authorization: Bearer` и `session.user.access_token`; событие `account_linking_complete_event`; длина ответа ограничена 5000 символов, OAuth-токен/refresh — 2048 символов (.../ru/auth/make-skill). Из документации.
- Состояние (п.6): `session_state` живёт до конца сессии; `user_state_update` между сессиями, **только для авторизованных Яндекс ID**; `application_state` привязан к `application_id` (устройство/приложение); удаление: `null` в `user_state_update`, `{}` для application_state; по 1 КБ каждый (.../ru/session-persistence). Из документации.

## 4. Аудиоплеер, потоковая музыка, фон

- В `meta.interfaces` есть поле `audio_player` («на устройстве есть аудиоплеер») (.../ru/request, .../ru/request-audioplayer). Из документации.
- Директив плеера в ответе (`AudioPlayer.*`, потоковые URL, форматы) в прочитанных страницах **нет**: не удалось проверить, поддерживается ли потоковое аудио навыком сейчас.
- Фон/музыка внутри ответа: только библиотека звуков (34 музыкальных элемента: арфа, гитара, скрипка, фортепиано, волынка, горн, барабаны, гонг, биты) через `<speaker audio="alice-music-harp-1.opus">` и свои загруженные звуки (≤120 с, ≤5 МБ) (.../ru/sounds/music, .../ru/resource-sounds-upload). Из документации. Непрерывной фоновой подложки под речью в документации не описано: **не удалось проверить**, можно ли накладывать звук поверх голоса.
- Совет платформы на долгую обработку: проигрывать фон из библиотеки, пока думает сервер (.../ru/wait-response).

## 5. Кнопки, картинки, карточки, экран

- Кнопки: `title` (обязателен, до 64 симв.), `url` (до 1024 байт), `payload` (до 4096 байт), `hide`; без `url` кнопка отправляет свой текст как реплику (.../ru/response). Из документации.
- Карточки: `BigImage` (одна картинка), `ItemsList` (1–5), `ImageGallery` (1–7) (.../ru/response). Из документации.
- Загрузка картинок (по поисковой выдаче на старую страницу tech.yandex.ru/dialogs/alice/doc/resource-upload-docpage, не по текущей): до 100 МБ на аккаунт, файл 1 КБ – 1 МБ, PNG/JPEG/GIF/BMP/TIFF/WEBP. Только из выдачи поиска — актуальность **не удалось проверить**.
- Экран: `meta.interfaces.screen`. С экраном — Алиса на Windows, приложение Яндекс, Яндекс Браузер; без экрана — Навигатор, Станция, Авто (.../ru/surfaces). Из документации. Механизма «запросить экран» (переезд диалога на устройство с экраном) в найденных страницах нет: **не удалось проверить**.
- Для безэкранных устройств `response.text` обязателен.

## 6. Хранение, идентификаторы, авторизация, внешняя БД

- См. дополнения выше: три state по 1 КБ; `user` — только для вошедших через Яндекс ID; `application_id` — экземпляр приложения/устройство (до 64 симв.) (.../ru/session-persistence, .../ru/request). Из документации.
- `session.user_id` в запросе помечен «не поддерживается» — использовать `application.application_id` (.../ru/request; в пересказе, перепроверить). `session.user.user_id` есть только при авторизации: уникален для пары пользователь–навык.
- Связка аккаунтов (OAuth): см. выше; ответ 5000 симв., токены 2048 симв. (.../ru/auth/make-skill).
- Внешняя БД: документация прямо допускает «собственный сервер разработчика» для неавторизованных (.../ru/session-persistence). Ключ — `application_id` (устройство), не человек. Из документации; конкретной рекомендации по БД (YDB и т.п.) нет.

## 7. Интеграция и хостинг

- Варианты: Yandex Cloud Functions, Azure, Google Cloud, AWS, Vercel, свой веб-сервер; примеры Node.js, Python, PHP, R, Go, Java, C#; есть визуальные конструкторы (.../ru/quickstart-about, .../ru/guides-and-examples). Из документации.
- Требования (HTTPS, сертификаты) на прочитанных страницах не детализированы: **не удалось проверить** (ссылки на deploy-ycloud-function, deploy-server — не открывались).
- Предел времени ответа 4,5 с включает соединение, доставку, обработку, ответ (.../ru/wait-response). Из документации. Холодный старт функции входит в эти 4,5 с — **проверить измерением**.
- Требование к качеству: не более 1 ошибки сервера на 10 запросов (.../ru/requirements).

## 8. События сессии, молчание, завершение, длительность

- `session.new`, `session_id` (до 64), `message_id` (счётчик). Выход: `end_session`, слова пользователя «стоп/хватит/вернись/закончить/выйти»; автовыход при ошибке формата и таймауте 4,5 с (.../ru/activation). Из документации.
- Таймаут молчания пользователя, «продолжи», максимальная длительность сессии: **не удалось проверить** — в прочитанных страницах чисел нет. Проект уже держит в записях «учтено и работает» для таймера колонки (см. CLAUDE.md проекта) — не перепроверял.
- Возобновление между сессиями возможно только через хранилище: `user`-состояние (нужен вход) или свой сервер по `application_id`.

## 9. Мультипользовательность

- Документация Диалогов не описывает различение говорящих в навыке: запрос содержит `application_id` (устройство), `user_id` только у авторизованных (один аккаунт). Признаков «голос говорившего» в полях запроса нет (.../ru/request). Из документации по отсутствию в найденном тексте.
- У самой Станции есть «запомни мой голос» для Музыки (справка Яндекса, поиск; не документация Диалогов) — в навык это не передаётся, насколько видно. Наш замер: одна колонка голоса не различает (CLAUDE.md проекта). Игроков придётся различать по репликам («ходит Вася»).
- Есть навыки-игры на нескольких игроков (Болталка с R2D2 — из выдачи поиска, не документация).

## 12. Публикация и модерация

- Публикация: создать навык в консоли → настройки (URL, фразы активации, голос, ограничения по поверхностям, каталог) → тестирование → модерация → публикация. После публикации в каталоге через 5–10 мин, в поиске в течение суток; правки ответов без модерации, правка конфигурации — через черновик и повторную модерацию (.../ru/publish, .../ru/publication). Из документации.
- Требования (.../ru/requirements): название 2–5 слов; активационные имена 2–4 слова; обязательны команды «Помощь» и «Что ты умеешь»; описание на русском, с контактами; допустимая доля ошибок сервера — не более 1 на 10; контент, подходящий по возрасту; запрещены оружие, наркотики, порнография, азартные игры, экстремизм и т.д.; публичные навыки проверяются целиком, приватные — только имена активации и иконка. Из документации.
- Возрастной рейтинг / режимы навыка: страницы publish не содержат: **не удалось проверить**.
- Есть `markup.dangerous_context` — пометка криминального подтекста в реплике; для фэнтези с мечами и убийствами имеет смысл посмотреть, как срабатывает — **проверить измерением**.

## Итог: возможность → пригодность для «Проклятого меча»

| Возможность | Пригодность | Нужно проверить измерением |
|---|---|---|
| Ответ до 1024 симв. text/tts, теги звуков не считаются | Ограничивает длину одного «куска» серии: серию режем на реплики по ходу диалога | Реальный предел tts на Станции (у нас 1024 замерено) |
| Таймаут 4,5 с | Все запросы к LLM/хранилищу должны укладываться, иначе сессия закрывается | Холодный старт функции, p95 времени ответа |
| Паузы `sil <[мс]>`, ударения `+` | Прямо годится для озвучки серий (ритм, драматические паузы) | Максимальная длина паузы, как звучит на Станции |
| Звуки из библиотеки (6 категорий, CC0) | Атмосфера: бой, шаги, природа, музыка | Слышимость на колонке, длительность звуков |
| Свои звуки (≤120 с, ≤5 МБ, 1 ГБ) | Заставки серий, музыка боя, звук меча | Качество после конвертации в OPUS, задержка |
| Эффекты голоса (megaphone, pitch_down, behind_the_wall, pulse …) | Кандидат для «голоса меча» и отдельных персонажей; **не работают на голосе Алисы** — нужен другой голос навыка | Звучание каждого эффекта на выбранном голосе; можно ли менять эффект по ходу ответа |
| Шёпот | Не найден в документации навыков (в статье Хабра шёпот — стиль синтеза Алисы, но не управляемый тег навыка) | Есть ли тег/голос со шёпотом; иначе имитация эффектом/громкостью текста |
